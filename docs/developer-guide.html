ShapeForms — Developer Guide

Extend, customize, and integrate with ShapeForms using hooks, filters, and the plugin's architecture.

Applies to Lite v1.1.8 · Pro v1.1.6 · Updated 2026-09-16

ShapeForms is designed with extensibility in mind. Every major operation — rendering, saving, validation, email — passes through WordPress filters and actions. This guide covers the public API surface available to developers.

Architecture

Plugin Bootstrap

The plugin initializes on plugins_loaded via a singleton pattern:

// shapeforms.php
function shapeforms_lite() {
    return ShapeForms_Lite::get_instance();
}
add_action( 'plugins_loaded', 'shapeforms_lite' );

Freemium Architecture & Extensions

ShapeForms is built as the free tier of a freemium product. ShapeForms Pro and third-party extensions hook into Lite without modifying its code. All extension points fire on the plugins_loaded hook via shapeforms_loaded, which passes the singleton instance:

add_action( 'shapeforms_loaded', function( $plugin ) {
    // $plugin is the ShapeForms_Lite singleton
    // Register your hooks, actions, filters here
    add_filter( 'shapeforms_allowed_field_types', function( $types ) {
        $types[] = 'my_custom_field';
        return $types;
    } );
}, 10, 1 );

Important: This is the canonical bootstrap hook for all extensions. It runs after ShapeForms's own hooks are in place, ensuring a stable foundation for your customizations.

Freemium teaser seams

Lite renders its upgrade prompts unconditionally — it never detects whether Pro is installed. An add-on removes or replaces a teaser by hooking a seam; there are two shapes:

  • Boolean gate — shapeforms_show_upgrade_cta: a single filter (default true) that guards every “Upgrade” prompt — the promo notice, admin menu item, toolbar button and page-header link, plus the builder's locked email/attachment/routing teasers. Pro simply calls add_filter( 'shapeforms_show_upgrade_cta', '__return_false' ) to hide them all at once, without Lite knowing which add-on is present.
  • Registry/data filter — shapeforms_integration_type_defs: Lite lists paid services as static teaser cards by flagging them 'pro' => true with empty fields. Pro's callback injects the real fields and unset()s the 'pro' flag, so the very same card renders as a live, configurable control instead of a locked teaser. (See Integration Hooks.)

Rule of thumb: a yes/no “show or hide” decision is a boolean gate; adding or modifying a set (fields, services, columns) is a registry filter. Both are standard WordPress filter idioms.

ShapeForms Pro — Architecture & Extension Model PRO

Pro is a separate plugin that extends Lite via the `shapeforms_loaded` hook and the module system. This section explains how Pro works and how it fits the freemium contract.

Pro Module System

Pro boots on Lite's shapeforms_loaded action (after a min-Lite-version compatibility check). On boot it instantiates each feature module into a registry, then — for every module whose is_enabled() returns true — calls register_hooks(), passing a shared ShapeForms_Pro_Loader. Each module implements:

interface ShapeForms_Pro_Module_Interface {
    // True when the license is valid AND this module's toggle is on.
    public function is_enabled();

    // Register this module's WordPress hooks via the shared loader.
    public function register_hooks( ShapeForms_Pro_Loader $loader );
}

// Example: the Payments module plugs into Lite's seams.
class ShapeForms_Pro_Payments implements ShapeForms_Pro_Module_Interface {
    public function is_enabled() { /* license + 'payments' toggle */ }
    public function register_hooks( ShapeForms_Pro_Loader $loader ) {
        $loader->add_filter( 'shapeforms_allowed_field_types', $this, 'register_field_types' );
        $loader->add_filter( 'shapeforms_field_control_html', $this, 'render_product_field', 10, 4 );
        $loader->add_filter( 'shapeforms_entry_data', $this, 'calculate_totals', 10, 3 );
    }
}

Modules are wired up in load_modules() (includes/class-shapeforms-pro.php); the Scheduling module boots slightly earlier via ShapeForms_Pro_Scheduling::boot() so it can gate form output before render.

How Pro Extends Lite (No Code Duplication)

Critical principle: Pro does NOT copy or duplicate Lite code. Instead:

  1. Pro registers field types via `shapeforms_allowed_field_types` filter
  2. Pro renders fields via `shapeforms_field_control_html` filter (Lite's rendering engine)
  3. Pro validates fields via `shapeforms_validate_field` filter
  4. Pro formats field display via `shapeforms_format_field_value` filter
  5. Pro hooks into submission via `shapeforms_entry_created`, `shapeforms_entry_data`, etc.

This means: Lite owns the core form engine; Pro plugs into it without modifying Lite's code.

Pro JavaScript Events

Pro modules re-initialize on these frontend events (see JavaScript Events & Extension Guide for the full picture of which are fired by Lite vs. Pro):

  • shapeforms_frontend_init Pro — convention signal (fired by Pro / 3rd-party) to initialize Pro widgets; not fired by Lite
  • shapeforms_step_loaded Pro — fired by the Pro multi-page module to re-init calculation/repeater on a new step
  • shapeforms_form_reset — fired by Lite after a successful submission; Pro listens to clean up its state

Form Migrator sources

The Form Migrator (Settings → Tools → Migrator) imports forms from other plugins into ShapeForms. Contact Form 7 ships as the first source; each additional source is one class implementing ShapeForms_Lite_Migration_Source and registered through the shapeforms_migration_sources filter. The controller stays source-agnostic: it lists every available source as a tab, and runs each imported form's plain rows/settings through the builder's own save path (ShapeForms_Lite_Ajax_Save::prepare_rows() and ::normalize_form_settings()) — a source never writes fields_json directly.

interface ShapeForms_Lite_Migration_Source {
    public function get_slug();        // 'cf7' — used in URLs, nonces, the migration marker
    public function get_label();       // 'Contact Form 7' (translatable)
    public function is_available();    // true when the source plugin/data is present
    public function get_forms();       // [ { id, title, imported } ]
    public function import_form( $id ); // { title, rows, settings, skipped[], source_id } | WP_Error
}

add_filter( 'shapeforms_migration_sources', function ( $sources ) {
    $sources[] = new My_WPForms_Migration_Source();
    return $sources;
} );

Idempotency is handled by the controller via an autoloaded shapeforms_migration_map option ("{slug}:{source_id}" => form_id), so a re-import updates the previously created form instead of duplicating it. A source only needs to describe how to read its own forms.

Conversational Forms

Conversational mode post-processes the already rendered form. It never re-renders, re-orders away or removes anything, so every field stays in the DOM — which is why conditional logic, validation and the submit path are untouched, and why field types added by an add-on work inside it with no changes on their side.

Screens are classified by what a row renders, not by field-type name:

Row rendersTreated as
No focusable control and no textStatic — never a screen; stays in the DOM and still posts (hidden fields, stripped page breaks)
No focusable control but has textStatement — a screen with nothing to answer
A focusable controlQuestion — an ordinary screen

This means a field type ShapeForms has never heard of behaves correctly with no registration at all. The filters below only refine the two cases structure cannot infer.

shapeforms_conversational_tail_types

Field types pinned to the final screen instead of getting one of their own. A consent box or captcha stranded mid-form leaves the visitor on a screen they cannot complete.

add_filter( 'shapeforms_conversational_tail_types', function ( $types ) {
    $types[] = 'order_summary';
    return $types;
} );

Default: captcha, terms_conditions.

shapeforms_conversational_stacking_types

Field types large enough that their row must never share a screen side by side.

add_filter( 'shapeforms_conversational_stacking_types', function ( $types ) {
    return array_merge( $types, array( 'signature', 'repeater', 'matrix' ) );
} );

Default: name, address, file.

shapeforms_conversational_enabled

Override whether conversational mode runs for a form, without changing the stored setting. Useful for disabling it site-wide or on specific templates.

add_filter( 'shapeforms_conversational_enabled', function ( $enabled, $settings, $form_id ) {
    return is_front_page() ? false : $enabled;
}, 10, 3 );
Conversational mode is embedded-only. ShapeForms registers no rewrite rules and no front-end URLs of its own — a conversational form renders in place, wherever the shortcode, block or widget sits. Nothing is added to your permalink structure and no path is claimed at your site root.

Notes for add-on authors

  • Per-form config travels in a data- attribute, not wp_localize_script(). A render-time localize is silently dropped under block (FSE) themes.
  • novalidate is applied from JavaScript only. The browser validates the whole form on submit, and an invalid required control inside a hidden screen cannot be focused — so the browser refuses to submit and reports nothing. Setting it from PHP would take native validation away from visitors without JavaScript.
  • Detect conditional hiding with element.style.display, never a visibility test: everything inside a hidden screen measures zero.
  • Per-screen styling is stored on whichever object IS the screen — the row when several questions share it, the field otherwise. Eleven keys in fields_json: eight cv_media_* (an attachment ID, never a URL, resolved at render time) and three colours (cv_bg, cv_question_color, cv_answer_color). The chrome colours are form-level only: every rule reading --bfc-btn, --bfc-btn-text, --bfc-accent, --bfc-track, --bfc-prev, --bfc-prev-bg and --bfc-hint is scoped to the wrapper, which is a screen’s ancestor, so a screen-level value could never reach one. A field-screen with no image of its own falls back to its row's.
  • cv_media_height uses 0 for the same purpose — the renderer omits --bfc-media-h entirely and the stylesheet's var( --bfc-media-h, min( 60vh, 460px ) ) fallback applies. Note it is deliberately NOT absint(): that returns the absolute value, so -400 would arrive as a deliberate-looking 400 instead of falling back to the default.
  • '' means INHERIT, and must be stored as ''. The renderer omits the custom property entirely for an empty value, so the form-level colour cascades in untouched. Storing a resolved copy of the form's colour instead would pin it — every screen would silently keep the old value the day the form default changed. The same rule governs the builder's controls: an untouched colour reads Form default and writes nothing.
  • The three screen colours are read at the point of use, so a screen overrides by cascade alone. Setting --bfc-question on a .shapeforms-cv-screen overrides it for that screen and nothing else — no extra selectors, no JS re-theming. The one exception is the background: --bfc-bg is consumed on the .shapeforms-cv wrapper, so a screen uses --bfc-screen-bg. Reusing the wrapper's name would make a screen repaint the wrapper's padding along with itself.
  • A colour control that renders over a fixed opacity is a control that lies. The “press Enter” hint is deliberately dimmed — 0.6 on the text, 0.8 on the key cap — so it does not compete with the button beside it, and that default has to be a faded inherit rather than a fixed grey, or it stops being legible the moment a form goes dark. Adding --bfc-hint on top of a literal opacity would give an author a washed version of the colour they picked. The fix is to tokenise the opacity: opacity: var( --bfc-hint-opacity, 0.6 ), with build_custom_properties() emitting --bfc-hint-opacity:1 only alongside a --bfc-hint that survived sanitize_hex_color(). Two fallbacks on one token cover both elements, and a form that sets no colour renders byte-identically.
  • A screen is a question, not a row. A row with more than one column becomes one screen, preserving the author's side-by-side layout. A single-column row holding several fields is split at runtime into one row per field. The split moves field nodes and clones only the row wrapper (and its media figure) — cloning a field would leave the conditional-logic evaluator driving a copy that is no longer on the page.
  • Register on shapeforms_preview_enqueue_assets as well as wp_enqueue_scripts. The admin form-preview screen is wp-admin, so wp_enqueue_scripts never fires there. Enqueueing a handle that was never registered still puts it in the queue — wp_script_is( $handle, 'enqueued' ) returns true and nothing is printed. Check 'registered' and a non-empty src, or assert on real printed output.
  • PHP's screen count is an upper bound on purpose. wrap_form_output() suppresses the chrome only when a form can never have more than one screen; the engine measures the live DOM and adds shapeforms-cv--inert (restoring the form to where it was rendered) when just one screen survives. Do not re-implement the split in PHP.

Submission Flow Hooks

The submission lifecycle in order:

  1. shapeforms_gate_submission — accept or reject before validation
  2. shapeforms_before_submission — fires before field validation
  3. shapeforms_submission_request — modify raw request payload
  4. shapeforms_entry_data — mutate validated entry data
  5. shapeforms_should_save_entry — control whether entry is persisted
  6. shapeforms_before_entry_save — last chance before DB insert
  7. shapeforms_entry_saved — after entry inserted
  8. shapeforms_entry_created — entry ID available, triggers integrations
  9. shapeforms_submission_result — filter the final JSON response

Checking a hook exists 1.1.5

Before hooking a newer extension point, ask ShapeForms whether it provides it — rather than comparing SHAPEFORMS_LITE_VERSION. That constant marks the last released version, so between releases it names a build that lacks a seam it actually has.

if ( method_exists( 'ShapeForms_Lite', 'supports' )
    && ShapeForms_Lite::supports( 'admin_email_attachments' ) ) {
    add_filter( 'shapeforms_lite_admin_email_attachments', 'my_addon_attach', 10, 4 );
}

The method_exists() guard matters — on a ShapeForms older than 1.1.5 the method itself is absent, which correctly reads as "no capabilities". Capability names are permanent once published.

Capabilities in this release: admin_email_recipient, admin_email_attachments, user_email_attachments.

Admin notification: recipient 1.1.5

Choose who the admin notification goes to, after the form's own settings have been applied — so a submission can be routed to different people based on what was answered. Return a single address, or several separated by commas.

// Route "Sales" enquiries to a different inbox.
add_filter( 'shapeforms_lite_admin_email_to', function( $to, $form_record, $entry_data, $entry_id ) {
    foreach ( $entry_data as $field ) {
        if ( 'Department' === $field['label'] && 'Sales' === $field['value'] ) {
            return 'sales@example.com, manager@example.com';
        }
    }
    return $to;
}, 10, 4 );

Whatever you return is re-validated before it is used. Each address must pass is_email() and survive sanitize_email() unchanged; any candidate containing CR/LF is discarded outright rather than cleaned up. That second rule matters because sanitize_email() repairs as readily as it rejects — a header-injection attempt such as a@evil.com\nBcc: v@x.com would otherwise be tidied into the valid-looking a@evil.comBccvx.com, an address nobody configured but that mail would really be delivered to. The same validation is applied to any Cc/Bcc line added via shapeforms_lite_admin_email_headers.

If the filtered value yields no valid address at all, the recipient the form already resolved is kept, so a notification is never lost. Note that the display-name form (Sales <sales@example.com>) is rejected — bare addresses only.

Admin notification: attachments 1.1.5

Add files to the admin notification — a generated PDF of the submission, an invoice, a copy of a contract. The filter receives the visitor's uploaded files, which ShapeForms attaches already, so add to the array rather than replacing it. Return absolute paths to files that already exist on disk; wp_mail() reads them while sending.

add_filter( 'shapeforms_lite_admin_email_attachments', function( $attachments, $form_record, $entry_data, $entry_id ) {
    $path = my_addon_write_pdf( $entry_id );   // must live under wp-content/uploads

    if ( $path ) {
        $attachments[] = $path;
    }

    return $attachments;
}, 10, 4 );

Paths are re-validated before use. Each one must resolve — through realpath(), so symlinks and ../ are followed to where they actually land — to a readable regular file inside the uploads directory. Anything else is dropped silently and the email still sends.

That boundary is deliberate. The return value becomes an outbound email attachment, so an add-on that builds a path from submitted data (or is simply buggy) could otherwise mail out wp-config.php. Write generated files under wp_get_upload_dir()['basedir'] — ideally a subdirectory of your own with a deny-all .htaccess, since uploads is web-readable — and delete them on shapeforms_after_notifications once the mail has gone.

The same filter exists for the user confirmation — shapeforms_lite_user_email_attachments, which passes $user_email before $entry_id (five arguments). Its list starts empty rather than inheriting the visitor's uploads, so add whatever you need explicitly.

Think before attaching there. That email goes to an address a stranger typed into a public form, so whatever rides along is delivered to whoever owns that address — including when it was mistyped. The admin notification goes to a known inbox; this one does not.

add_filter( 'shapeforms_builder_localize_data', function( $data ) {

Custom Validation

ShapeForms provides multiple validation hooks for different scopes:

Per-Field Validation

Use shapeforms_validate_field to validate a single field before the entry is saved. The filter receives ($error, $value, $field, $request) — the field's id and type are on the $field array. Return a non-empty string (the error message) to fail validation; return the unchanged $error (empty by default) to pass.

add_filter( 'shapeforms_validate_field', function( $error, $value, $field, $request ) {
    if ( 'number' === ( $field['type'] ?? '' ) && 'age' === ( $field['id'] ?? '' ) ) {
        if ( absint( $value ) < 18 ) {
            return 'You must be 18 or older.';
        }
    }
    return $error;
}, 10, 4 );

Form-Level & Entry Data Validation

Use shapeforms_gate_submission for form-level checks (reject the whole submission), or shapeforms_entry_data to mutate validated data before save:

add_filter( 'shapeforms_gate_submission', function( $gate, $form_id, $settings, $request ) {
    if ( 5 === $form_id ) {
        $age = absint( $request['shapeforms_age'] ?? 0 );
        if ( $age < 18 ) {
            return array( 'success' => false, 'message' => 'You must be 18 or older.' );
        }
    }
    return $gate;
}, 10, 4 );

End-to-End Add-On Tutorial: Custom Validation Field

Build a complete, shippable add-on that adds a custom "Phone" field with validation and formatting.

Step 1: Register the Field Type

add_filter( 'shapeforms_field_library', function( $library ) {
    $library['phone'] = array(
        'label'  => 'Phone (US)',
        'icon'   => 'dashicons-phone',
        'group'  => 'basic',
        'pro'    => false,
    );
    return $library;
} );

Step 2: Whitelist the Field for Save

add_filter( 'shapeforms_allowed_field_types', function( $types ) {
    $types[] = 'phone';
    return $types;
} );

Step 3: Render on Frontend

add_filter( 'shapeforms_field_control_html', function( $html, $type, $field_name, $field ) {
    if ( 'phone' !== $type ) {
        return $html;
    }

    $value = isset( $_POST[ $field_name ] ) ? sanitize_text_field( $_POST[ $field_name ] ) : '';
    $required = ! empty( $field['required'] ) ? ' required' : '';

    return '<input type="tel" id="' . esc_attr( $field_name ) . '" name="' . esc_attr( $field_name ) . '" value="' . esc_attr( $value ) . '" pattern="[0-9\-\(\)\s]+"' . $required . ' placeholder="(123) 456-7890">';
}, 10, 4 );

Step 4: Add Validation

The filter receives ($error, $value, $field, $request); return a non-empty string to fail.

add_filter( 'shapeforms_validate_field', function( $error, $value, $field, $request ) {
    if ( 'phone' !== ( $field['type'] ?? '' ) ) {
        return $error;
    }

    // Remove non-digits for validation
    $digits_only = preg_replace( '/[^\d]/', '', $value );

    // US phone: 10 digits
    if ( strlen( $digits_only ) !== 10 ) {
        return 'Please enter a valid 10-digit US phone number.';
    }

    return $error;
}, 10, 4 );

Step 5: Format for Display

add_filter( 'shapeforms_format_field_value', function( $formatted, $value, $field_type ) {
    if ( 'phone' !== $field_type ) {
        return $formatted;
    }

    // Format: (123) 456-7890
    $digits = preg_replace( '/[^\d]/', '', $value );
    if ( strlen( $digits ) === 10 ) {
        return sprintf( '(%s) %s-%s', substr( $digits, 0, 3 ), substr( $digits, 3, 3 ), substr( $digits, 6 ) );
    }

    return $value;
}, 10, 3 );

Step 6: Display in Admin Entries List

add_filter( 'shapeforms_entry_value_admin_html', function( $html, $value, $field_type, $field ) {
    if ( 'phone' !== $field_type ) {
        return $html;
    }

    $digits = preg_replace( '/[^\d]/', '', $value );
    $formatted = strlen( $digits ) === 10 ? sprintf( '(%s) %s-%s', substr( $digits, 0, 3 ), substr( $digits, 3, 3 ), substr( $digits, 6 ) ) : $value;

    return '<a href="tel:' . esc_attr( $value ) . '">' . esc_html( $formatted ) . '</a>';
}, 10, 4 );

Hook Stability & Deprecation Policy

All hooks listed in the Hook Reference Table are part of ShapeForms's public API and are stable.

Stability Guarantee

  • Shipped hooks never disappear. If a hook is released, it remains available in all future releases.
  • Hook signatures don't change. The number and order of parameters are fixed; new parameters are added only at the end (for filters) or as new hooks.
  • Hook behavior is predictable. The timing and context of hook execution don't change between versions.

Deprecation Process

If a hook must be retired (very rare), the deprecation follows this process:

  1. Notice Phase (1 minor version): The hook is marked deprecated in the codebase; a `_deprecated_hook()` call alerts developers via WordPress debug logs.
  2. Grace Period (1 major version): The hook still fires and works normally, but deprecation notices are logged.
  3. Removal: The hook is removed in the next major version (e.g., v2.0.0).

@since Markers

Every hook in the Hook Reference Table includes a @since version (e.g., "1.0.0", "1.1.0"). This tells developers which version introduced the hook. If you depend on a hook added in v1.1.0, you can safely assume it exists in v1.1.0+.

Third-Party Extensions

If you ship an extension (plugin, theme, or SaaS integration) that uses ShapeForms hooks:

  • Target a minimum version. Document which version of ShapeForms your extension requires.
  • Check for hook existence. Use has_filter() or has_action() before calling dynamic hooks.
  • Use @since markers as a reference. Don't use hooks released after your stated minimum version.

JavaScript Events & Extension Guide

ShapeForms's frontend fires a single jQuery event that extensions can hook into. Two additional events listed below are a shared convention used by ShapeForms Pro modules — Lite itself does not fire them, but documenting them here lets you write one extension that works in both Lite and Pro forms.

EventFired byTargetDetail / Use
shapeforms_form_resetLite (frontend)documentFired after a successful AJAX submission and form reset; args [ $form ]. Use to clean up custom state.
shapeforms:form_settings_renderedLite (builder)documentformSettings object — fired when the Settings panel renders; used to inject Pro setting tabs. Builder only.
shapeforms:before_saveLite (builder)documentformSettings object — builder only; attach handlers to inject extra keys before save.
shapeforms_frontend_init ProPro / 3rd‑partydocumentConvention signal that a form was (re)injected into the DOM. Pro field modules listen to (re)initialize widgets. Not fired by Lite.

Hooking into the Lite reset event

In a Lite-only install, the event you can rely on is shapeforms_form_reset, fired on document after a successful submission:

jQuery( document ).on( 'shapeforms_form_reset', function( e, $form ) {
    // $form is the jQuery-wrapped form element. Clean up custom widget state here.
    MyWidget.cleanup( $form );
} );

Writing an extension that also works on Pro forms

If your widget needs to (re)initialize when Pro injects or re-renders a form (e.g. multi-step navigation or repeater rows), also listen for the Pro convention events. They are harmless in a Lite-only install — they simply never fire:

// Runs on initial load and again whenever Pro (re)injects / advances the form.
jQuery( document ).on( 'shapeforms_frontend_init shapeforms_step_loaded', function( e, formEl ) {
    var $form = jQuery( formEl );
    MyWidget.init( $form );
} );

The Double-Bind Guard Pattern

Because the convention re-init events (shapeforms_frontend_init / shapeforms_step_loaded) can fire more than once for the same form, guard your initializer so it only runs once per form element:

jQuery( document ).on( 'shapeforms_frontend_init', function( e, formEl ) {
    var $form = jQuery( formEl );
    // Check if already initialized
    if ( $form.data( 'mywidget_initialized' ) ) {
        return; // Skip if already done
    }

    // Initialize the widget
    MyWidget.init( $form );

    // Mark as initialized
    $form.data( 'mywidget_initialized', true );
} );
